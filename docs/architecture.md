# Architecture

`@umbra-escrow-and-dispute-window/umbra-sdk` provides the TypeScript client and off-chain hashing primitives for the Umbra protocol on Stellar.

## Module Map

```
src/
├── index.ts        Public surface aggregating all client functions, types, and error classes
├── umbra.ts        Primary Umbra client class, hire workflow, and waitForState polling
├── types.ts        Shared configuration, signer interfaces, and parameter models
├── errors.ts       Typed error hierarchy extending UmbraError
├── hashing.ts      Canonical JSON (RFC 8785 subset) and domain-separated SHA-256 digests
├── deployments.ts  Vendored contract addresses and network passphrases
└── generated/      Vendored TypeScript contract client generated by stellar-cli
```

## Error Hierarchy

All custom errors emitted by the SDK inherit from `UmbraError`:

```
Error
 └── UmbraError (has readonly code: string)
      ├── SignerRequiredError (code: "SIGNER_REQUIRED")
      ├── StateTimeoutError (code: "STATE_TIMEOUT")
      └── ContractCallError (code: "CONTRACT_CALL_FAILED")
```

- **`SignerRequiredError`**: Thrown when a state-mutating call (such as `hire`) is invoked without a configured `publicKey` and `signTransaction`.
- **`StateTimeoutError`**: Thrown by `waitForState` when the target state is not observed within `timeoutMs`. Exposes `escrowId`, `targetState`, and `timeoutMs`.
- **`ContractCallError`**: Represents Soroban contract simulation or invocation rejections, capturing the on-chain error code where available.

## Transaction Life Cycle

Soroban methods exposed by `Umbra` return an `AssembledTransaction<Result<void>>`:

1. **Simulation**: Calling `umbra.confirm(escrowId)` simulates the transaction against the RPC node without broadcasting.
2. **Inspection**: The caller can inspect simulation results, fees, and resource footprints before signing.
3. **Execution**: Calling `.signAndSend()` signs the transaction envelope via the configured `signTransaction` callback and broadcasts it to the network.
